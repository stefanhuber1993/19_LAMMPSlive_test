Chapter 7

Occlusion: ambient and the sun

Two questions, one pass, half resolution. "How much of the sky can this point see?" and "can it see the sun?" — both answered by poking around in the depth buffer.

What ambient occlusion is for

Chapter 9's lighting has an ambient term: a constant blue-grey fill, sky_ambient = (0.30, 0.38, 0.52), standing in for light arriving from the whole sky rather than from the sun. Applied uniformly, it is a lie. A point deep in a crevice between three touching beads cannot see much sky — the beads are in the way — so it should receive far less of that fill than a point on an exposed cap.

Ambient occlusion is a scalar per pixel, 0 to 1, meaning "what fraction of the hemisphere above this surface is open?" Multiply the ambient term by it and crevices darken. In a dense bead cloud this is not decoration: it is most of what tells you which beads are touching and which merely overlap on screen.

Computing it properly means integrating visibility over a hemisphere, which means ray-tracing the scene. Screen-space ambient occlusion does it with about eight texture lookups instead, by asking the G-buffer.

The algorithm, step by step

1. Get the surface

vec3 P = texture(posTex, uv).xyz;
if (P.z >= -1e-4) { frag = vec2(1.0); return; }              // background
vec3 N = normalize(texture(normalTex, uv).xyz);

Sky is fully open and fully lit: (1, 1), and out. This early-out matters — on a typical sheet frame more than half the screen is background.

2. Build a tangent frame

float rot = hash12(gl_FragCoord.xy);
vec3 rv = normalize(vec3(cos(rot * 6.283), sin(rot * 6.283), 0.0));
vec3 T = normalize(rv - N * dot(rv, N));
vec3 B = cross(N, T);
mat3 TBN = mat3(T, B, N);

The samples must land in the hemisphere above the surface, never inside it, so they need a coordinate frame whose z axis is N. Line three is Gram–Schmidt: take an arbitrary vector rv, subtract off its component along N (N * dot(rv, N) is that component), and what remains is perpendicular to N. Normalise, take a cross product for the third axis, and mat3(T, B, N) is a rotation matrix that maps "up" in sample space to N in view space.

The arbitrary vector is chosen by the per-pixel hash, so neighbouring pixels sample rotated versions of the same pattern. That is the noise-instead-of- pattern principle from chapter 6, and without it eight samples produce eight visible bands.

3. Distribute the samples

vec2 xi = fract(vec2(float(i) * 0.7548776662,
                     float(i) * 0.5698402909) + rot);
float r = sqrt(xi.x);                        // cosine-weighted hemisphere
float phi = 6.2831853 * xi.y;
vec3 h = vec3(r * cos(phi), r * sin(phi), sqrt(max(1.0 - xi.x, 0.0)));

Check that h is a unit vector: its length squared is r² + (1 − xi.x) = xi.x + 1 − xi.x = 1. So the samples sit on the unit hemisphere shell, all at the same distance from P, spread over directions.

The distribution is cosine-weighted: because xi.x is uniform and h.z = √(1 − xi.x), the density of directions is proportional to cosθ from the normal. That is Malley's method, and it is the right weighting because the ambient light a surface receives from a direction is itself weighted by cosθ — a grazing ray delivers less energy per unit area. Sampling in proportion to the weight means every sample contributes equally, so you need no per-sample weight in the sum.

4. Project and compare

vec3 sp = P + TBN * h * radius;
vec2 suv = view_to_uv(sp);
if (suv.x < 0.0 || suv.x > 1.0 || suv.y < 0.0 || suv.y > 1.0) continue;
float sz = texture(posTex, suv).z;
if (sz >= -1e-4) continue;                   // background: occludes nothing
float sd = -sz, sampleDist = -sp.z;
if (sd < sampleDist - bias)
    occ += smoothstep(0.0, 1.0, radius / max(abs(sampleDist - sd), 1e-4));

This is the heart of it, and it is only three ideas:

  1. Where would this 3D sample appear on screen? view_to_uv, chapter 6.
  2. What is the nearest surface there? One texture lookup.
  3. Is that surface nearer than my sample? If yes, my sample is inside something — buried — so that direction is blocked.

The bias (0.08 × r = 0.04 σ) stops a sample sitting a hair above a curved surface from being judged buried by its own bead — the classic self-occlusion acne. The smoothstep is the range check: the weight is 1 while the occluder is within radius of the sample and falls off beyond, so a bead six σ in front of this crevice does not darken it. Drop that term and every silhouette in the image grows a dark halo, because the background just behind a bead's edge would be "occluded" by the bead.

5. Average

frag.x = clamp(1.0 - occ / float(nSamples), 0.0, 1.0);

Fraction blocked → fraction open. Note this raw value is not the number used for shading; chapter 9 raises it to the power ao_strength = 5.83 first, which pins fully-open surfaces at 1.0 and bends only the partly occluded ones down.

The scales, in real units

ao_radius_r = 2.0 means the hemisphere has radius 2 × 0.5 = 1.0 σ — two bead radii, so it reaches a neighbouring bead's surface and no further. At d = 12 σ that projects to 1.0 × 444.4 / 12 = 37 pixels on screen, or 18.5 at the half resolution the pass runs at. So each pixel is scattering eight lookups over an 18-pixel neighbourhood. Far enough to find the crevice, close enough that the lookups stay in cache.

The _r suffix convention in RenderStyle is doing real work here: quoting the radius in bead radii is what lets the same style file drive a 0.5 σ MesoMem bead and a 1.0 Å ion without retuning.

Contact shadows, in the same pass

The second half of the shader answers a different question with the same machinery: can this point see the sun?

float sun_visibility(vec3 P, vec3 N, vec3 L) {
    if (shadowOn < 0.5 || dot(N, L) <= 0.0) return 1.0;
    const int STEPS = 16;
    vec3 origin = P + N * shadowBias;
    float jit = hash12(gl_FragCoord.xy);
    for (int i = 0; i < STEPS; ++i) {
        float f = (float(i) + jit) / float(STEPS);
        vec3 sp = origin + L * (shadowLen * f * f);
        ...
        if (dz > shadowBias && dz < shadowThick) return 0.0;
    }
    return 1.0;
}

Walk from the surface toward the sun in sixteen steps. At each step, ask the G-buffer what the nearest surface at that screen position is. If it is in front of the step, something is standing between this point and the sun.

Four details, each earning its place

dot(N, L) <= 0 returns early. A surface facing away from the sun gets no diffuse light anyway (max(dot(N,L), 0) in chapter 9 is zero there), so marching would be sixteen lookups spent on a number that gets multiplied by zero. This one line skips roughly half the lit pixels.

Start along the normal, not along the light.

// Start along the NORMAL, not along the light: near a silhouette the light
// can graze back across this very bead and the ray then reports the surface
// shadowing itself (classic acne).

Offsetting along L keeps you on the surface when the light grazes it, and the first step promptly finds "an occluder" — the bead you are standing on. Offsetting along N lifts you clear of the surface regardless of the light angle. The lift is 0.08 × 0.5 = 0.04 σ.

Quadratic step spacing. This is the nicest idea in the function. With shadowLen = 5.5 × 0.5 = 2.75 σ:

Compare a linear march: 16 equal steps over 2.75 σ is 0.172 σ each, which is a third of a bead radius — so the very contact you are trying to render, the dark seam where two beads touch, falls entirely between the first two steps and is missed. The quadratic spacing puts five steps inside the first tenth of a radius and still reaches five radii out. Same sixteen lookups, precision exactly where the eye is looking.

The thickness guess.

if (dz > shadowBias && dz < shadowThick) return 0.0;

dz is how far in front of the step the stored surface sits. Positive means something is in the way. But the depth buffer only records a front surface; it has no idea how deep that object goes. If you accepted any positive dz, a bead in the far background would be shadowed by a bead in the foreground twenty σ nearer, which is nonsense — the ray passes well behind it. So the renderer assumes occluders are shadow_thick_r = 2.6 bead radii thick (1.3 σ) and ignores anything further in front than that. It is a guess. It is the guess every screen-space shadow implementation has to make.

Why both live in one half-resolution pass

aw, ah = max(1, width // 2), max(1, height // 2)
self.ao_tex = c.texture((aw, ah), 2, dtype="f2")

410×450 = 184,500 pixels instead of 738,000: a quarter of the work for both terms. That is legitimate because both are broad, low-frequency signals — neither ambient occlusion nor a soft contact shadow has detail at the pixel level — and both get blurred immediately afterwards anyway.

Two channels of one texture, not two textures: one framebuffer, one draw, one blur downstream. And they share the expensive parts — the background test, the normal fetch, the hash12. Bundling them is free.

The comment adds the reason that actually forced the design:

"it rides in this pass, at half resolution, so that the AO blur downstream smooths BOTH terms. That matters more here than for the AO: the march below is a binary hit, jittered per pixel, so on its own it comes out as dithered noise along every shadow edge, and blurring is what turns that noise back into a soft penumbra."

Follow that through, because it is a genuinely elegant piece of engineering. sun_visibility returns 0 or 1 — there is no soft shadow anywhere in it. The softness comes entirely from the jitter making neighbouring pixels disagree, and the blur then averaging their disagreement. Nine of sixteen neighbours in shadow becomes 0.56. A penumbra, synthesised out of a binary test and a box filter.
