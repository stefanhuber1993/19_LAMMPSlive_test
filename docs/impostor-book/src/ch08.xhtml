Chapter 8

The blur that must not leak

Sixteen lines, one nested loop, and one if that is the difference between soft shading and a glowing halo around every bead.

Why blur at all

Chapter 7 produced two noisy signals. The ambient occlusion is noisy because eight samples cannot integrate a hemisphere accurately; the sun visibility is noisy because it is a jittered binary test. Both are, by construction, low-frequency quantities — occlusion varies over the scale of a bead, not a pixel. Averaging over a neighbourhood therefore costs almost no real signal and removes almost all of the noise. It is the cheapest possible denoiser and exactly the right one.

vec2 sum = vec2(0.0);
float wsum = 0.0;
for (int x = -2; x < 2; ++x)
    for (int y = -2; y < 2; ++y) {
        vec2 o = uv + vec2(x, y) * texel;
        float fg = texture(posTex, o).z < -1e-4 ? 1.0 : 0.0;
        sum += texture(aoTex, o).rg * fg;
        wsum += fg;
    }
frag = wsum > 0.0 ? sum / wsum : texture(aoTex, uv).rg;

Sixteen taps in a 4×4 box, at half resolution, so it reaches eight full-res pixels — a fair fraction of the 37-pixel occlusion radius. Both channels (.rg) are filtered together, because they are two channels of one texture. A box blur, not a Gaussian: for a signal with no high frequencies in it to begin with, the difference is invisible and the box is a third of the instructions.

The halo, and the one line that prevents it

Now the important part. Recall chapter 7's first line: background pixels return (1.0, 1.0) — fully open, fully lit. That is correct as a value. It is poison as a blur input.

Consider a pixel just inside the silhouette of a bead. Its own occlusion is, say, 0.4 — it is near the rim, partly shadowed by its own bead and its neighbours. But half of its 4×4 neighbourhood is background, sitting at 1.0. A naive average gives roughly (8×0.4 + 8×1.0)/16 = 0.7. The rim pixel has been lightened, and so has every rim pixel all the way around every bead. The result is a bright fringe hugging every silhouette — and since it follows the geometry, it reads unmistakably as a glow.

The fix is to make the blur a weighted average and to give background taps a weight of zero:

float fg = texture(posTex, o).z < -1e-4 ? 1.0 : 0.0;
sum  += texture(aoTex, o).rg * fg;
wsum += fg;
...
frag = sum / wsum;

Now the rim pixel averages only the eight foreground taps and stays at 0.4. The blur is confined inside the geometry and cannot cross a silhouette. This is the same idea as a bilateral filter — weight taps by whether they belong to the same surface — in its simplest possible form, using the free coverage mask from chapter 5.

The fallback matters too. If every tap is background, wsum is zero and sum / wsum is a NaN. NaNs are contagious: they survive multiplication, they survive mix, and one of them can turn a whole pixel black or white for the rest of the frame. Hence:

frag = wsum > 0.0 ? sum / wsum : texture(aoTex, uv).rg;

Take the unblurred value, which is (1, 1) for background anyway. Guarding a division whose denominator can go to zero is not paranoia in a shader; it is the only debugging you get, since you cannot print anything.

An asymmetry worth noticing. for (int x = -2; x < 2; ++x) runs over −2, −1, 0, 1 — four values, but not centred on zero. The kernel is offset half a texel toward the lower-left. For a signal this smooth, half a texel at half resolution is invisible, which is presumably why it has never mattered. It is still the kind of off-by-one that would be a real bug in a sharper filter, and worth spotting when you read shader loops.

Where the LINEAR filter comes in

for t in (self.ao_tex, self.ao_blur_tex):
    t.filter = (c.LINEAR, c.LINEAR)

The G-buffer textures are NEAREST (chapter 5); these two are LINEAR, for the opposite reason. The composite pass runs at full resolution and samples this half-resolution texture, so every second full-res pixel falls between texels. With NEAREST you would see the half-resolution grid as visible 2×2 blocks in the shading. With LINEAR the hardware interpolates for free and the upsample is invisible.

That is the half-resolution trick completed: sample at half res, blur at half res, and let the texture unit's bilinear filter do the reconstruction on the way out. Three quarters of the work saved, no visible difference.

Skipping the whole thing

self.ao_fbo.clear(1.0, 1.0, 1.0, 1.0)
ao_tex = self.ao_tex
if style.ao_samples > 0 or style.shadows:
    ... render ssao, then blur ...
    ao_tex = self.ao_blur_tex

If a style switches both terms off, neither pass runs and the composite reads the cleared texture — which is (1, 1), meaning "fully open, fully lit", exactly the identity for both terms. The disabled path needs no branch in the composite shader and no separate code path. Choosing your clear value to be the identity of the operation that consumes it is a small, reusable trick.

An exercise for later

A box blur is separable: a 4×4 box is a horizontal 4-tap followed by a vertical 4-tap, 8 taps instead of 16. The mask does not break this, because both the numerator (sum) and the denominator (wsum) are themselves box-filtered quantities and can be separated independently — you would carry three channels through an intermediate texture. Whether that is worth an extra full-screen pass at 184,500 pixels is a genuinely open question; measure it before you believe either answer.
