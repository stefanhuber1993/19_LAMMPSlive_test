Chapter 10

Depth of field

A lens can only focus one distance at a time. Everything else smears into a disc, and the size of that disc is the entire effect.

The circle of confusion

A pinhole camera — which is what chapter 2's projection describes — has infinite depth of field: every point maps to exactly one point, sharp everywhere. A real lens has aperture, and only points at one particular distance converge back to a single point on the sensor. A point nearer or further converges in front of or behind the sensor plane, so by the time it reaches the sensor it has spread into a small disc. That disc is the circle of confusion, and its radius is what you have to compute.

float coc_of(vec3 P) {
    if (P.z >= -1e-4) return 1.0;                   // background: fully blurred
    return clamp(abs(-P.z - focus) / range, 0.0, 1.0);
}

Distance from the focus plane, divided by a range, clamped — a linear ramp rather than the physically correct hyperbola. In a scene 16 σ deep with a maximum blur of three pixels, the difference between linear and physical is invisible, and the linear version gives you two intuitive knobs instead of an f-number and a sensor size.

The knobs are quoted, like the depth cue's, as fractions of the scene's own depth span:

def focus_range(self, d_front, d_back):
    span = max(d_back - d_front, 1e-4)
    return d_front + self.dof_focus * span, max(self.dof_range * span, 1e-4)

For the sheet (dof_focus = 0.25, dof_range = 1.5, dof_bokeh_px = 6.0) over 11.911 to 28.077 σ:

span   = 16.166 σ
focus  = 11.911 + 0.25 × 16.166  = 15.95 σ
range  = 1.5 × 16.166            = 24.25 σ
CoC at the near edge  = |11.911 − 15.95| / 24.25 = 0.167  → 1.0 px
CoC at the far edge   = |28.077 − 15.95| / 24.25 = 0.500  → 3.0 px

Gathering the disc

const int TAPS = 24;
const float GA = 2.39996323;
float radius = coc * maxCoc;

vec3 sum = c0.rgb;
float wsum = 1.0;
for (int i = 1; i <= TAPS; ++i) {
    float t = float(i) / float(TAPS);
    float a = float(i) * GA;
    vec2 off = vec2(cos(a), sin(a)) * sqrt(t) * radius * texel;
    ...
}

Twenty-four samples on a spiral. Two details make it work:

The golden angle. 2.39996323 radians is 137.5°, 2π/φ². Advance by this angle each step and successive points never line up into spokes — it is the most irrational rotation there is, which is exactly why sunflower seeds use it. Any rational fraction of a turn (say 90°) would put every fourth sample on the same ray and produce a visible star.

sqrt(t). If the radius grew linearly with t, the samples would be evenly spaced along the spiral, which means densely packed near the centre — the area of an annulus grows as r, so uniform radial spacing over-samples the middle. Taking the square root spaces them uniformly by area. The same √ appeared in chapter 7's hemisphere for the same reason, and it will keep appearing: whenever you map a uniform random number to a radius, you want its square root.

Gather versus scatter, honestly

Here is the interesting compromise, and the comment states it more clearly than most published descriptions of the technique:

float w = max(coc_of(texture(posTex, uv + off).xyz), 0.05);
sum += texture(colorTex, uv + off).rgb * w;
wsum += w;

"Weight each tap by its OWN circle of confusion, so a blurry foreground bleeds outward instead of being clipped off by a sharp background pixel. Not exact — physically an out-of-focus foreground SCATTERS over the background, and a gather filter like this one can only pull inward — but it removes the tell-tale hard edge around near objects, which is the 90%-for-5% version of the fix."

Unpack that. Physically, an out-of-focus point spreads outward onto its neighbours — a scatter. But a fragment shader can only write to its own pixel; it cannot deposit light on its neighbours. So every practical implementation inverts the problem into a gather: instead of asking "where does my light go?", each pixel asks "whose light lands on me?"

The inversion is only exact if every contributing pixel has the same circle of confusion. At a depth discontinuity — a blurred bead in front of a sharp background — it is not. A naive gather would let a sharp background pixel dominate the average right up to the bead's edge, and the blurred bead would end up with a razor-sharp outline: unmistakably wrong. Weighting each tap by its own CoC means a blurry tap contributes strongly and a sharp one weakly, which approximately restores the outward bleed. The max(..., 0.05) floor keeps a fully sharp neighbourhood from summing to zero.

It is not correct. It is close enough that you will not notice, and correct scattering costs a sorted per-pixel accumulation buffer.

Two early-outs

if (enabled < 0.5) { frag = c0; return; }
float coc = coc_of(texture(posTex, uv).xyz);
if (coc < 0.02) { frag = c0; return; }          // already sharp

Full-screen passes live and die by early-outs. Pixels near the focus plane skip 24 texture fetch pairs entirely, so the cost scales with how much of the frame is actually out of focus rather than with the frame.

The uniform-driven enabled branch is uniform across every invocation, so the GPU's branch predictor handles it perfectly — there is no divergence penalty when all threads in a warp take the same path. The coc < 0.02 branch does diverge at the boundary between sharp and blurred regions, where some pixels in a warp exit early and some do not; those warps pay for both paths. That is fine, because such warps are a thin band around the focus plane.

Blur that stays the same size

DOF_REFERENCE_HEIGHT = 900.0
...
d["maxCoc"].value = (style.dof_bokeh_px * self.height / DOF_REFERENCE_HEIGHT)

A blur radius in pixels is not a property of the picture; it is a property of the picture at a particular size. Go fullscreen at 1600 px tall with a fixed 6-pixel bokeh, and every bead is now nearly twice as big while the blur is not — the image gets visibly sharper. Scaling maxCoc with the viewport height keeps the blur the same fraction of the picture.

This is the same instinct as the outline threshold in chapter 9 and the _r-suffixed AO radii in chapter 7: express every visual parameter in units that do not change when something irrelevant does. Blur as a fraction of the frame, occlusion as a multiple of the bead radius, outlines as a fraction of the on-screen radius, depth ramps as fractions of the scene's depth. That single discipline is why three very different scenes can share one style file.

Where it sits in the chain

self.lit_tex.use(0)      # the composite's output
self.pos_tex.use(1)      # the G-buffer position, still needed for the CoC
self.shaded_fbo.use()
self._fs_vaos[self.dof_prog].render(mode=c.TRIANGLES, vertices=3)

DoF reads the composited image, which is why the composite renders to lit_fbo rather than straight to the output — you cannot blur a picture you have not finished painting. And it still reads the G-buffer position texture, six passes downstream from the geometry that wrote it. The G-buffer is not consumed; it stays live for the whole frame.

It also runs before the lines, which is deliberate and slightly opinionated: chapter 12 has the argument.
